# 衛生管理者試験対策サービス 問題データ設計書

作成日: 2026年8月29日
バージョン: v0.1(初版)
対象DB: Supabase (PostgreSQL)

---

## 1. 設計方針

- 第一種・第二種の両区分に対応できるよう、「区分」を独立したマスタで管理する
- 分野(労働衛生・関係法令・労働生理 等)もマスタ化し、問題・商品の両方から参照する
- 過去問/独自作成の区別を出典として保持し、著作権管理・品質管理をしやすくする
- 苦手分野連動型アフィリエイトのため、分野マスタと商品マスタを紐づける
- Supabase の Row Level Security (RLS) で、ユーザー固有データ(進捗・復習リスト・模試結果)を保護する

---

## 2. テーブル一覧

| テーブル名 | 役割 |
|---|---|
| `exam_types` | 資格区分マスタ(第一種/第二種/共通) |
| `categories` | 分野マスタ(労働衛生/関係法令/労働生理 等) |
| `questions` | 問題本体 |
| `choices` | 選択肢(問題に紐づく) |
| `products` | アフィリエイト商品マスタ |
| `category_products` | 分野と商品の紐づけ(多対多) |
| `users` (Supabase Auth標準) | ユーザー情報(Supabase Authが自動管理) |
| `user_progress` | ユーザーごとの分野別正答率・演習回数 |
| `user_answers` | ユーザーの個別回答履歴 |
| `review_list` | 復習リスト(間違えた問題の管理) |
| `mock_exams` | 模試セット定義 |
| `mock_exam_results` | ユーザーの模試結果 |
| `study_logs` | 学習カレンダー用の日次学習記録 |

## 3. テーブル定義

### 3.1 exam_types(資格区分マスタ)

| カラム名 | 型 | 説明 |
|---|---|---|
| id | uuid (PK) | 区分ID |
| code | text | 区分コード('type1', 'type2', 'common') |
| name | text | 表示名(例:「第一種衛生管理者」) |

### 3.2 categories(分野マスタ)

| カラム名 | 型 | 説明 |
|---|---|---|
| id | uuid (PK) | 分野ID |
| exam_type_id | uuid (FK → exam_types.id) | どの区分に属する分野か(共通分野もあり) |
| name | text | 分野名(例:「労働衛生(有害業務)」) |
| sort_order | int | 表示順 |

### 3.3 questions(問題本体)

| カラム名 | 型 | 説明 |
|---|---|---|
| id | uuid (PK) | 問題ID |
| exam_type_id | uuid (FK → exam_types.id) | 対応区分(第一種のみ/第二種のみ/共通) |
| category_id | uuid (FK → categories.id) | 分野 |
| question_text | text | 問題文 |
| explanation | text | 解説文 |
| source_type | text | 出典区分('past_exam' = 過去問整形 / 'original' = 独自作成) |
| source_note | text (nullable) | 出典の詳細(例:「令和5年度 第2種 問12」) |
| difficulty | int (nullable) | 難易度(1〜5等、任意) |
| created_at | timestamp | 作成日時 |
| updated_at | timestamp | 更新日時 |

### 3.4 choices(選択肢)

| カラム名 | 型 | 説明 |
|---|---|---|
| id | uuid (PK) | 選択肢ID |
| question_id | uuid (FK → questions.id) | 対象問題 |
| choice_text | text | 選択肢の文言 |
| is_correct | boolean | 正解フラグ |
| sort_order | int | 表示順 |

### 3.5 products(アフィリエイト商品マスタ)

| カラム名 | 型 | 説明 |
|---|---|---|
| id | uuid (PK) | 商品ID |
| name | text | 商品名 |
| asp | text | ASP種別('amazon' / 'rakuten') |
| affiliate_url | text | アフィリエイトリンク |
| image_url | text (nullable) | 商品画像URL |
| product_type | text | 種別('book' / 'course' / 'goods' 等) |
| exam_type_id | uuid (nullable, FK → exam_types.id) | 対応区分(区分を問わない商品はnull) |
| is_active | boolean | 表示可否(廃盤・リンク切れ対応用) |
| priority | int | 表示優先度(同一分野内での並び順) |

### 3.6 category_products(分野⇔商品の紐づけ)

| カラム名 | 型 | 説明 |
|---|---|---|
| id | uuid (PK) | 紐づけID |
| category_id | uuid (FK → categories.id) | 分野 |
| product_id | uuid (FK → products.id) | 商品 |

※ 苦手分野連動レコメンドは「ユーザーの正答率が低いcategory_id」→「category_productsで紐づくproduct_id」を取得するロジックで実現する。

### 3.7 user_progress(ユーザー進捗)

| カラム名 | 型 | 説明 |
|---|---|---|
| id | uuid (PK) | ID |
| user_id | uuid (FK → auth.users.id) | ユーザー |
| category_id | uuid (FK → categories.id) | 分野 |
| total_answered | int | 累計回答数 |
| total_correct | int | 累計正答数 |
| updated_at | timestamp | 最終更新日時 |

※ `total_correct / total_answered` で正答率を算出し、苦手分野判定・レコメンドに利用する。

### 3.8 user_answers(回答履歴)

| カラム名 | 型 | 説明 |
|---|---|---|
| id | uuid (PK) | ID |
| user_id | uuid (FK) | ユーザー |
| question_id | uuid (FK) | 問題 |
| selected_choice_id | uuid (FK) | 選んだ選択肢 |
| is_correct | boolean | 正誤 |
| answered_at | timestamp | 回答日時 |

### 3.9 review_list(復習リスト)

| カラム名 | 型 | 説明 |
|---|---|---|
| id | uuid (PK) | ID |
| user_id | uuid (FK) | ユーザー |

| added_at | timestamp | 追加日時(直近の誤答日) |

| カラム名 | 型 | 説明 |
|---|---|---|

## 4. 苦手分野連動レコメンドのロジック(概要)

1. `user_progress` から、対象ユーザーの `total_correct / total_answered` が閾値(例:60%未満)の `category_id` を抽出
2. `category_products` を介して、該当 `category_id` に紐づく `product_id` を取得
3. `products.is_active = true` かつ `priority` 順に並べて表示
4. 表示箇所(模試結果画面・復習リスト画面等)に応じて件数を絞り込む(例:上位2〜3件)

---

## 5. RLS(Row Level Security)方針

- `user_progress` / `user_answers` / `review_list` / `mock_exam_results` / `study_logs` は、`user_id = auth.uid()` の行のみ本人がアクセス可能に設定
- `questions` / `choices` / `categories` / `exam_types` / `products` / `category_products` は全ユーザー読み取り可能(マスタデータのため)
